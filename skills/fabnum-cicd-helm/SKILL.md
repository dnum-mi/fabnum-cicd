# Helm charts with fabnum-cicd

Help the user wire the lifecycle of a Helm chart: checks, versioning, publication, signing. Detailed docs (in French),
to read before writing a call: `../../docs/workflows/11-lint-helm.md`, `12`, `20`, `51` to `54`, `56`.
The constraints of a specific deployment platform (admission rules, quotas) are not covered here.

> Relative links to `docs/` assume the full repository. Without it (URL install, or only the skills copied), the same
> pages are online: <https://github.com/dnum-mi/fabnum-cicd/tree/main/docs>.

## Where does the chart live? (first question)

| Situation | Workflow chain |
|-----------|----------------|
| Chart **in the application repository** (monorepo) | `update-helm-chart` (`RUN_MODE: local`) → `release-helm-local` (OCI) |
| Chart in a **separate repository**, triggered by the app | app repository: `dispatch-helm-chart`; chart repository: an entry workflow that calls `update-helm-chart` (`RUN_MODE: called`) |
| **Dedicated chart repository**, published to OCI and/or GitHub Pages | `release-helm` (chart-releaser) |

Do not use `release-helm` in an application monorepo: the application's tags drown chart-releaser's change
detection. Chart and application versions are **deliberately decoupled**.

## Check

- `lint-helm`: `ct lint` + check of the README generated by helm-docs. `CT_CONF_PATH` (`chart-testing` config) is
  required; `CHARTS_DIR` must match the `chart-dirs` of that config.
- `lint-helm-schema`: validates the values against a JSON Schema (`CHART_PATH` required).
- `test-helm`: `ct install` in a Kind cluster (`CT_CONF_PATH` required).
- All three: `permissions: contents: read`.

## Monorepo: bump then publish

```yaml
  bump-chart:
    uses: dnum-mi/fabnum-cicd/.github/workflows/update-helm-chart.yml@v0
    needs: [release, build]
    if: ${{ needs.release.outputs.release-created == 'true' }}
    permissions:
      contents: write
      pull-requests: write          # required even in local mode (union of permissions)
    with:
      RUN_MODE: local
      CHART_NAME: <chart>
      CHART_DIR: charts
      APP_VERSION: ${{ needs.release.outputs.version }}
    secrets:
      APP_CLIENT_ID: ${{ secrets.APP_CLIENT_ID }}
      APP_PRIVATE_KEY: ${{ secrets.APP_PRIVATE_KEY }}

  release-chart:
    uses: dnum-mi/fabnum-cicd/.github/workflows/release-helm-local.yml@v0
    needs: [bump-chart]
    permissions:
      contents: read
      packages: write
    with:
      CHARTS_DIR: charts
      CHART_NAME: <chart>
      CHECKOUT_REF: ${{ needs.bump-chart.outputs.commit-sha }}
```

- `update-helm-chart` exposes `chart-version`, `previous-chart-version` and `commit-sha` (`local` mode only).
- `release-helm-local` creates neither a tag nor a release; it refuses to overwrite an already published version
  (`ALLOW_OVERWRITE: false`). With a registry other than `ghcr.io`, `REGISTRY_USERNAME` / `REGISTRY_PASSWORD` are required.
- If the repository has a pre-release branch, the bump job **commits to `main`**: list it in the `needs` of
  `sync-prerelease-branch` (skill `fabnum-cicd-release`).

## Chart in a separate repository

On the **application repository** side (the App must be installed on the chart repository, skill `fabnum-cicd-auth`):

```yaml
  dispatch-chart:
    uses: dnum-mi/fabnum-cicd/.github/workflows/dispatch-helm-chart.yml@v0
    needs: [release]
    if: ${{ needs.release.outputs.release-created == 'true' }}
    permissions: {}
    with:
      CHART_REPO: <org>/<chart-repo>          # owner/repo form is mandatory
      CHART_NAME: <chart>
      CHART_DIR: charts
      APP_VERSION: ${{ needs.release.outputs.version }}
      # BASE_BRANCH: develop                  # if the chart repository's default branch is not main
    secrets:
      APP_CLIENT_ID: ${{ secrets.APP_CLIENT_ID }}
      APP_PRIVATE_KEY: ${{ secrets.APP_PRIVATE_KEY }}
```

On the **chart repository** side, `.github/workflows/update-app-version.yml` (name expected by default; otherwise
pass `WORKFLOW_NAME`) must declare **all** the inputs the dispatch sends, otherwise the API rejects the dispatch (422):

```yaml
name: Update app version

on:
  workflow_dispatch:
    inputs:
      RUN_MODE: { required: false, default: called }
      APP_VERSION: { required: false }
      CHART_NAME: { required: true }
      CHART_DIR: { required: false, default: charts }
      UPGRADE_TYPE: { required: false, default: auto }
      PRERELEASE_IDENTIFIER: { required: false, default: rc }
      AUTOMERGE_PRERELEASE: { required: false, default: "false" }
      AUTOMERGE_RELEASE: { required: false, default: "false" }
      AUTOMERGE_METHOD: { required: false, default: auto }

jobs:
  update-chart:
    uses: dnum-mi/fabnum-cicd/.github/workflows/update-helm-chart.yml@v0
    permissions:
      contents: write
      pull-requests: write
    with:
      RUN_MODE: called
      CHART_NAME: ${{ inputs.CHART_NAME }}
      CHART_DIR: ${{ inputs.CHART_DIR }}
      APP_VERSION: ${{ inputs.APP_VERSION }}
      UPGRADE_TYPE: ${{ inputs.UPGRADE_TYPE }}
      PRERELEASE_IDENTIFIER: ${{ inputs.PRERELEASE_IDENTIFIER }}
      AUTOMERGE_PRERELEASE: ${{ inputs.AUTOMERGE_PRERELEASE == 'true' }}
      AUTOMERGE_RELEASE: ${{ inputs.AUTOMERGE_RELEASE == 'true' }}
      AUTOMERGE_METHOD: ${{ inputs.AUTOMERGE_METHOD }}
      BASE_BRANCH: ${{ github.ref_name }}
    secrets:
      APP_CLIENT_ID: ${{ secrets.APP_CLIENT_ID }}
      APP_PRIVATE_KEY: ${{ secrets.APP_PRIVATE_KEY }}
```

- The dispatch is **asynchronous**: the application job is green as soon as the dispatch is accepted. Check the run on
  the chart side (`gh run list -R <org>/<chart-repo>` if `gh` is available).
- With an App token, the bump PR triggers the chart repository's CI (with `GITHUB_TOKEN`, it does not).

## Dedicated chart repository

`release-helm`: at least one active channel among `CREATE_GITHUB_RELEASE` (default `true`: a GitHub release per chart +
`index.yaml` on `PAGES_BRANCH`, which must **already exist**) and `PUBLISH_OCI`. Documented pitfalls:

1. **GitHub Pages is public even on a private repository**: `index.yaml` exposes the chart names and versions there. Prefer OCI alone.
2. `CREATE_GITHUB_RELEASE: true` is **incompatible with immutable releases**: use `PUBLISH_OCI: true` alone.
3. `SIGN_CHART` (GPG) requires `CREATE_GITHUB_RELEASE`, `SIGNING_KEY_ID`, `GPG_PRIVATE_KEY` and `GPG_PASSPHRASE`.

## Sign and attest (OCI)

`attest-helm`: cosign signature and SLSA provenance of charts already published to an OCI registry. `CHARTS` required;
permissions `packages: write`, `id-token: write`, `attestations: write`. Call it after publication, with the
`published-charts` output of `release-helm` or `release-helm-local`.
